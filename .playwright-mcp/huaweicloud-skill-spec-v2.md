条)\n\n类别\t数量\t特征\t示例\n应触发\t8-10 条\t变体措辞(正式 / 口语 / 缩写 / 错字);直接点名 vs 隐含需求;简短 vs 长上下文;单步 vs 多步\t\"我的 ECS 卡死了怎么办\" / \"帮我把这台服务器重启一下\"\n不应触发\t8-10 条\t近失(near-miss):共享关键词但任务不同\t\"帮我改一下安全组规则\"(若技能只做诊断)、\"把日志传到 OBS\"(若技能只管 ECS)\n\n② 测触发率:每条查询跑 ≥3 次,触发率 = 命中次数 / 运行次数;应触发项 >0.5 通过、不应触发项 <0.5 通过(依据 Agent 执行日志 / 工具调用记录判定是否加载了该 SKILL.md)。\n\n③ 防过拟合:查询集按 60/40 拆分为 train / validation;只用 train 失败指引修改;避免把失败查询的关键词直接抄进 description(那是过拟合),要找关键词背后的通用类别。\n\n④ 优化循环(约 5 轮):应触发失败 → 描述太窄,扩大范围 / 补充适用语境;不应触发误报 → 描述太宽,明确\"不做什么\"边界。每轮校验仍在 1024 字符内。\n\n⑤ 结果应用:更新
